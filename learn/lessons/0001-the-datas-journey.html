Lesson 1 · factory-edge-gateway

The data's journey

Follow one real reading, a lathe spindle turning at 599 RPM, from a machine you've never seen to a page on your laptop. By the end you can draw the whole pipeline from memory.

Where the data comes from

The data starts at real CNC machines: an Okuma lathe and a Mazak mill. They are not in your house. They're attached to a public server run by the MTConnect Institute, demo.mtconnect.org. Open that link: it's live.

That server runs an MTConnect agent, software that collects machine readings and serves them over plain HTTP as XML.[1] Every reading gets a sequence number, a counter that only goes up. The agent remembers the last 131,072 readings in a ring buffer, so older ones are overwritten.[1] On this demo that's roughly 45 minutes of history.

You first asked for NIST's test bed. It was offline, and the demo agent speaks the same protocol, so the program takes the agent's address as a setting (-agent).

The seven hops

  1. Somewhere elseMachine → MTConnect agentThe Okuma reports spindle speed 599. The agent stamps it with sequence number, say, 33,653,231.
  2. Raspberry Pi · cmd/edgeAgent → edge programEvery second the edge program asks the agent: "give me everything after sequence N". It turns each reading into a small JSON record.
  3. Raspberry Pi · DockerEdge → KafkaIt writes the record into a Kafka topic called mtconnect.observations. Only after Kafka confirms the write does the edge program advance N and save it to disk.
  4. Raspberry Pi · DockerKafka holds itKafka is a durable log. Reading a record doesn't delete it; it stays for 24 hours here.[2] This is why your laptop can be off and miss nothing.
  5. The networkKafka → Tailscale → your MacTailscale makes a private, encrypted network containing just your Mac and your Pi.[3] The Mac reaches the Pi at raspberrypi.taileb9175.ts.net from any Wi-Fi, with no ports opened on your router.
  6. Your Mac · cmd/consumerConsumer → SQLiteThe consumer reads new records and saves them to observations.db. Only then does it tell Kafka "I've got up to here" (a commit).
  7. Your Mac · browserSQLite → status pageThe consumer also runs a tiny web server. 127.0.0.1:8090 shows the latest value of every reading, refreshing every 2 seconds.

Why so many pieces?

Each one answers a "what if":

What if…What saves you
the laptop is off for an hourKafka keeps the records until you read them
the Pi loses internet for 10 minutesthe agent's buffer still has those sequence numbers
the laptop changes Wi-FiTailscale finds the Pi wherever it is
a program crashes mid-writeboth sides only move forward after the next hop confirms

That last row is the core idea of the whole project. Lessons 3 and 4 dig into it.
