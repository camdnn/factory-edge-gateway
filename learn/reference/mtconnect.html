MTConnect cheat sheet

Just the parts of MTConnect this pipeline uses.

Requests

RequestReturnsEdge uses it
/currentlatest value of every data itemfirst run, after a gap
/sample?from=N&count=Cevery observation from N, at most Cevery poll (C = 1000)
/probethe device and data item listnot used

Header fields

FieldMeaning
instanceIdchanges when the agent restarts; numbering starts over
bufferSizehow many observations the ring buffer holds (demo: 131,072 ≈ 45 min)
firstSequenceoldest observation still held
lastSequencenewest observation held
nextSequencewhere the next /sample should start

What a poll does (Client.Next)

Cursor vs headerOutcomeMissed
no cursor yet/current snapshot, no gapn/a
network errorkeep cursor, retry next second0
instanceId differsgap: agent restarted, re-snapshotunknowable (0)
next < firstSequence or OUT_OF_RANGEgap: fell behind, re-snapshotnew next − old next
otherwisekeep all, cursor = nextSequence0

Gaps go to the pipeline.gaps topic in the same batch as the observations. The cursor {instance_id, next} is saved to edge-cursor.json only after Kafka acks.
